# Ember Godot — правила для AI-агентов

Этот репозиторий — единственный активный проект Ember и источник правды о коде,
данных и текущем состоянии. История чата его не заменяет.

## Начало нетривиальной задачи

1. Прочитать этот файл, `docs/README.md` и короткий `docs/EMBER_NOW.md`.
2. Проверить `git status --short` и последние релевантные коммиты.
3. Через `rg` найти владельцев данных, runtime/editor paths, Resources,
   serialization и targeted tests.
4. По `docs/README.md` открыть только нужные разделы больших документов.
5. Составить и согласовать короткий Task Contract по `docs/EMBER_WORKFLOW.md`:
   ожидаемый результат, существующие owners, границы, проверки и ручная приёмка.

До исследования и согласования контракта код не менять. Отдельный task-файл
без доказанной необходимости не создавать.

## Ответственность и делегирование

Основной агент в текущем thread сам ведёт исследование, обсуждение, изменения,
проверки и передачу результата. Субагенты и worker-thread, включая read-only
исследование и review, запрещены без отдельной явной просьбы пользователя
для конкретной задачи. Обычное «делай» и прежние разрешения её не заменяют.
Не предлагать делегирование по умолчанию и не перекладывать передачу контекста
между агентами на пользователя.

При явно запрошенном исключении заранее назвать модель, reasoning effort
и границы; одновременно работает только один пишущий worker. Worker не
расширяет контракт, не начинает следующую feature и не делает commit/push
без переданной авторизации. Вопросы игрового ощущения, масштаба, schema/owner
и других решений пользователя он передаёт основному агенту с рекомендацией
и последствиями. Отчёт возвращается координатору напрямую; если канала нет,
worker даёт пользователю короткий готовый текст для передачи. Worktree нужен
лишь для независимого среза по решению координатора с заранее описанным
возвратом изменений; обычно работа идёт в текущем дереве Godot.
Подробный процесс — `docs/EMBER_WORKFLOW.md`.

## Документы

`docs/README.md` — карта документации. `docs/EMBER_NOW.md` хранит только
текущую точку, открытые проверки и ближайшие шаги. Долговечное направление
продукта принадлежит `docs/EMBER_PRODUCT_PLAN.md`, правила игры —
`docs/EMBER_GAME_DESIGN.md`, действующие технические owners и риски —
`docs/EMBER_TECHNICAL_HANDOFF.md`. Массовый authoring мира, planners,
биомы и большие 3D world brushes принадлежат одному документу —
`docs/EMBER_WORLD_AUTHORING_ARCHITECTURE.md`. Подробные gates —
в релевантном разделе `MIGRATION_TEST_PLAN.md`.

После принятого среза переписывать NOW как текущую точку, не добавлять
хронологию. Не размножать один контракт в разных документах: соседним
достаточно короткой ссылки. Новый markdown создавать только для
самостоятельного долговечного домена. При сокращении старого файла сначала
сохранить действующую истину у её канонического владельца; Git хранит
superseded-детали.

## Неподвижные границы

- Runtime и authoring — Godot 4 Forward+.
- Карты принадлежат `.tscn`; voxel-источник — `content/voxel_models/*.tres`
  (`EmberVoxelModelResource`). Mesh, collision, thumbnail, prefab и
  MeshLibrary — производные данные.
- `../joi-conductor/content/ember` читает только legacy-importer до закрытия
  `docs/EMBER_JOI_EXIT_PLAN.md`; новые runtime-зависимости от JOI запрещены.
- Не добавлять второй renderer, voxel editor, owner механики или схему данных.
  Общая математика живёт в одном чистом leaf-модуле; UI маршрутизирует команды.
- Preview совпадает с commit. Тяжёлая операция фиксируется один раз на
  pointer-up/Enter. На мелкий input не делать full remesh/reload; большие
  операции измерять и чанкировать на репрезентативной карте.
- Editor-only состояние не попадает в gameplay Resource без решения о
  владельце. Цвет группы — authoring metadata, цвет вокселей — palette data.
- Collision, высота и navigation игрока/AI используют одну физическую
  поверхность.

Изменение данных закрывать вертикально: Resource/schema → validation →
editor → preview/runtime → serialization → targeted tests → документация.

## Проверка и безопасность

Editor-срез требует Undo/Redo, save/reopen, discard, validation и targeted
test; затем связанных regressions и ручного Forward+ для UI/render/physics/
input. Тесты используют fixtures и `user://`, а не авторские карты.
Автоматический PASS не заменяет ручную визуальную или игровую приёмку.

Не удалять пользовательские изменения, не форматировать массово и не применять
`git reset`/`checkout --`. Менять только файлы согласованного среза. Commit,
branch и push — только по явной просьбе пользователя.

Никогда не запускать рабочий checkout через `--headless --editor`. Targeted
tests запускать через `--headless --path . --script ...`; editor/import smoke —
только в отдельном checkout/cache. Пока `at-icons` отключён, сохранять
`addons/at-icons/.gdignore`.

## Закрытие контракта и смена основного thread

Контракт закрыт после нужных проверок, ручной приёмки и обновления
долговечных документов и NOW. Основной thread может вести последовательные
контракты одного milestone. Один контракт не дробить между координаторами.

Новый основной thread предлагать лишь когда контекст уже мешает работе или
начинается крупный milestone; до передачи зафиксировать состояние в Git,
канонических документах и NOW. Смена координатора — только с согласия
пользователя по `.agents/skills/ember-coordinator-handoff/SKILL.md`:
новый агент сначала read-only пересказывает точку проекта и стиль работы,
старый исправляет расхождения. До принятой передачи старый thread остаётся
координатором и не архивируется.
