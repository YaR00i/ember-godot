# Ember Godot — правила для AI-агентов

Этот репозиторий — единственный активный проект Ember. Перед изменениями читать
`docs/EMBER_PRODUCT_PLAN.md`, `docs/EMBER_TECHNICAL_HANDOFF.md` и релевантный
раздел `MIGRATION_TEST_PLAN.md`.

## Рабочие процессы

- Перед нетривиальной задачей выбрать подходящий маршрут в
  `docs/EMBER_WORKFLOW.md`: функция, исправление ошибки, контент,
  производительность или миграция.
- Для editor UI и игрового UI дополнительно следовать
  `docs/EMBER_UI_PIPELINE.md`. Нативный Godot — основной путь; HTML применяется
  только для согласования крупного player-facing интерфейса, когда он реально
  помогает проверить композицию и состояния до переноса.
- До реализации коротко объяснить пользователю ожидаемый результат, границы
  текущего среза и способ проверки. Вопросы задавать после изучения проекта,
  небольшими порциями, с рекомендацией и понятными последствиями вариантов.

## Граница проекта

- Целевой runtime и authoring — Godot 4 Forward+.
- Карты после переноса принадлежат `.tscn`; voxel-источник —
  `content/voxel_models/*.tres` (`EmberVoxelModelResource`). Mesh, collision,
  thumbnail, prefab и MeshLibrary — производные данные.
- `../joi-conductor/content/ember` разрешено читать только legacy-importer-у до
  закрытия `docs/EMBER_JOI_EXIT_PLAN.md`. Runtime, preview и сохранение нового
  контента не должны получать новые зависимости от JOI.
- Не добавлять новый renderer, второй voxel editor или параллельную схему данных.

## Как менять контракт

Сначала найти существующую реализацию и тесты через `rg`. Изменение данных
закрывается вертикально: Resource/schema → normalization/validation → editor →
preview/runtime → serialization → targeted tests → документация.

- Общая математика живёт в одном чистом leaf-модуле; UI только маршрутизирует
  команды.
- Preview обязан совпадать с commit. Тяжёлая операция фиксируется один раз на
  pointer-up/Enter, не при каждом движении.
- Editor-only состояние (выделение, скрытие, камера, срез) не сериализуется в
  gameplay Resource без отдельного решения о владельце.
- Цвет группы — authoring metadata, цвет самих вокселей — palette data; не
  смешивать их.
- Collision, высота и navigation игрока/AI должны использовать одну физическую
  поверхность.
- Не делать полную remesh/reload карты на мелкий input; долгие операции должны
  быть чанкированы и проверены на большой карте.

## Приёмка

Для каждого редакторского среза обязательны Undo/Redo, save/reopen, discard,
validation и targeted headless test. Затем прогнать связанные Surface/Graph/
runtime тесты и вручную проверить Forward+ viewport, если менялся UI или render.
Не перезаписывать авторские карты ради теста: использовать fixtures и `user://`.

## Рабочая осторожность

Рабочее дерево может содержать незавершённые пользовательские изменения. Не
удалять, не форматировать массово и не применять `git reset`/`checkout --`.
Перед правкой смотреть `git status --short`; менять только файлы своего среза.
Не коммитить и не отправлять изменения без отдельной просьбы пользователя.

- Никогда не запускать этот рабочий checkout через `--headless --editor`: такой
  запуск меняет editor-themed import variants и провоцирует повторный импорт в
  GUI. Targeted tests запускать через `--headless --path . --script ...`, а
  editor/import smoke — только в отдельном checkout или import cache.
- Пока plugin `at-icons` отключён, сохранять `addons/at-icons/.gdignore`, чтобы
  его 3 708 SVG не участвовали в обычном asset scan.

## Текущий порядок

1. Основной editor получил stop-line в v2.56. Не продолжать общую полировку без
   конкретного production workflow, который текущие инструменты не позволяют
   выполнить.
2. Провести отдельную последовательную Q&A-сессию с пользователем и собрать
   подтверждённые решения в единый игровой дизайн-документ.
3. По дизайн-документу собрать первую D3 physical-зону.
4. Переносить только нужные production-зоне G1/G2-партии после read-only
   inventory, strict parity и визуального согласования реальных prefab changes.
5. Затем закрыть G4/G5: удалить runtime fallback на JOI и пройти тест без
   sibling-репозитория.
