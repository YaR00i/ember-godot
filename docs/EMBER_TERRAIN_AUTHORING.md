# Ember — земля и материалы

Тематический вход на 2026-09-30. Здесь — действующий путь компактной земли,
материалов и его открытые проверки. Это не журнал итераций и не план будущего
массового мира. Текущая задача — в `EMBER_NOW.md`, будущие planners — в
`EMBER_WORLD_AUTHORING_ARCHITECTURE.md`, технические owners — в handoff.

## Компактная земля

- Одна сцена имеет один активный источник земли. Compact Resource содержит
  высоту, верхний/базовый материал и воду; voxel-объекты сохраняют прежнюю схему.
- `EmberMapLoader.compact_terrain` исключает плотную Surface этой карты.
  Вид, collision и высота выводятся из одних данных и треугольников.
- Обычная земля хранит 16×16 колонок на игровой блок. Основной профиль кисти
  меняет квадраты 8×8, средний — 2×2, детальный — отдельные колонки.
  Ступень высоты 4 или 8 вокселей; квадратный/круглый след выбирается отдельно.
  Профиль editor-only; цвет и вода не выравнивают высоту.
- 32 voxels/block остаются выбором для необычных voxel-деталей. Старые Resources
  не переводятся массово. Test Pier не переносится автоматически.
- `scenes/terrain_region_pilot.tscn` — отдельный пилот, не production-карта.
  Первый scene-owned перенос — `scenes/landscape_compact.tscn` и её `.res`.
  Отвергнутый Landscape V2 не возобновлять через bake после каждого мазка.

## Создание и расширение карты

По согласованному контракту от 2026-10-03 реализована основа большой карты:
созданные участки 24×24 м хранятся в единственном compact terrain Resource.
Ориентир островов — 256–512 м с прежним масштабом блока. Генератор одной области
реализован ниже; сохраняемый план нескольких областей ещё впереди. Порядок —
`EMBER_WORLD_AUTHORING_ARCHITECTURE.md` → «Большая карта как управляемый план областей».

«+ Карта» создаёт отдельные `.tscn` и `.res`: ID, 1–4 участка по каждой оси,
участок 24×24 блока. Есть ровная земля и берег; берег задаёт сушу, воду,
неровности и seed. Preview и создание используют одни подготовленные данные;
при записи они раскладываются по адресным участкам без изменения результата.
Рецепт не сохраняется для скрытой повторной генерации.

«+ Участок» включает выбор места в 3D по сетке 24×24 м: щелчок — один квадрат,
протягивание — несколько, до 4×4 за раз. Синие квадраты новые, серые уже заняты.
«Далее: рельеф и вода» / Enter открывает параметры и exact preview; кнопка
«Изменить выделение» возвращает к области, Esc/отмена не меняют карту.
Параметры холмов/хребтов/изрезанных склонов и уровня воды управляют общей формой
только новых участков; занятая земля сохраняет высоты, материалы и поток.
Применение — одна команда Undo; выбранная область остаётся доступной кистям.
Окно закрывает WorldEditor только после успешного применения: автоматическое
закрытие AcceptDialog до `confirmed` отключено, чтобы не потерять candidate.
При отказе причина остаётся видна в окне; предпросмотр нужно подготовить заново.
Внешние пустые адреса не получают землю/воду/коллизию. Переход к прежней земле
строится со стороны новой области. Рост слева/сверху компенсируется transform
Map и обратным сдвигом групп, сохраняя прежние мировые позиции земли/объектов.
Размер берётся из текущего terrain draft; Apply согласует scene metadata.
Discard возвращает размер и только сдвиги Map/Terrain/Props/Regions, сделанные
добавлением; независимые перемещения не откатываются. Текущий editor recovery
хранит эти сдвиги, Save принимает расстановку как baseline. Сохранение с открытым
preview снимает временные transforms до упаковки сцены.
Старый recovery без новых данных сдвига не восстанавливает потерянные позиции
западного/северного расширения; такая копия требует ручной проверки anchors.
Ctrl+Z создания карты не удаляет созданные файлы — это принятый поток.
Старый плотный формат читается без перезаписи; добавление адресного участка
переводит черновик в schema 2, файл меняется только при явном Save. Новые карты
сразу пишут schema 2. Предел адресов сейчас 22 по оси (оболочка 528 м), не
обещание производительности заполненного острова такого размера.

Автоматические и отдельные native Forward+ проверки: частичный край, пустой
адрес, точная отмена западного сдвига, кисть/Undo/Redo, Save/Reopen/Discard,
совпадение preview/Apply и F6-проход через стык. Ровная 4×4 карта: 576 tile,
headless сборка ~0,91 с, худший измеренный кадр ~7 мс (не замер живого ввода).
Далёкая разреженная оболочка проверена на шести участках, включая физику и путь;
полностью заполненные 256–512 м и слабый ПК OPEN. Новый прямой выбор проверен
отдельным native fixture: мышь/Enter/Back/Esc/камера, смешанная область,
настоящую OK-кнопку (включая видимый отказ устаревшего candidate), preview=Apply,
мировой стык слева/сверху, Undo/Redo, оба пути Save с preview,
Discard/Reopen и F6 с коллизией новой земли. Панель/параметры при 125% помещаются
в 1600×900 и 1280×750. Удобство автора и художественная оценка стыка OPEN.
Пробные поля воды перенесены на созданные участки с halo и общим графом моря.
Прежний отдельный отказ выше 120 м снят; контрольная 192×120 м проверена в
native preview/Apply/Undo/Save/Reopen/F6. Повторное добавление после Apply без
выхода из редактирования разрешено. Подготовка идёт в фоне, готовые материалы
подключаются постепенно; детали и открытые большие/слабый ПК gates —
Water Rendering → «Действующий путь пробы».

## Генератор рельефа выбранной области

Нативная кнопка «Сгенерировать рельеф…» использует прежнее выделение
«Область и вид → Ограничить участок». Без выделения берётся вся карта, если
она не больше 96×96 м. Пустые адреса сначала добавляются через «+ Участок»;
кнопка существующей области не расширяет карту. «+ Участок» использует тот же
generator job для новых адресов; отдельного editor/renderer нет.
Размер всей области берётся из текущего terrain-черновика, а не из
`authored_size_blocks`: старые пробные сцены могут иметь иной размер в metadata.
Уже открытый до обновления Godot нужно перезапустить для появления новой кнопки.

Одна область получает остров с нерегулярной овальной основой, морем и берегом.
Режимы: мягкие холмы (многомасштабный шум), горные хребты (ridged noise),
изрезанные склоны (приближение следов эрозии с конечными производными и warp,
по мотивам Swiss turbulence, не точная реализация Uber Noise/NMS и не
гидравлическая симуляция). Размер острова, горизонтальный масштаб форм,
высота суши/рельефа, берег, море и seed разделены; числа высоты — метры от
основания карты. Общий sampler также сохраняет прежний рецепт «+ Карта → Берег».

Кнопка предпросмотра готовит приватный candidate по участкам; расчёт групп
8×8 колонок идёт с бюджетом около 4 мс. Preview использует прежний tile mesher
и реальные материалы, без новых физических объектов. Изменение параметров
отменяет устаревший preview и требует явного обновления; Apply использует
готовый candidate без повторной генерации и создаёт одну Undo-команду.
Этот путь также проверен через OK-кнопку AcceptDialog; окно закрывается после
commit. Прямой вызов сигнала `confirmed` не проверяет порядок закрытия окна.
Существующая земля у границы выделения сохраняет крайнюю группу и получает
переход шириной 2 м; внешний край всей карты может уйти под море. Вне области
все каналы земли сохранены; лимит высот при необходимости увеличивается как
метаданные, не перемещая прежнюю землю и не перестраивая неизменные tile.

Генерация заменяет внутри области землю, покрытия, воду, поток и side overrides;
объекты остаются на прежних местах и могут потребовать авторской перестановки.
Нужны явно назначенные роли грунта/травы/песка/камня; цвета старых карт не
классифицируются автоматически. Вода наследует имеющийся слот; сухой стандартный
compact-пресет использует прежний слот 5. Результат сохраняется обычным Save
в том же terrain Resource. Параметры окна пока не сохраняются как план области;
при F6 никакой скрытой генерации нет.
Точка входа и сохранённая позиция при запуске поднимаются до той же физической
земли, если генерация подняла её выше прежнего старта. Авторский маркер не меняется;
это не автоматическая перестановка остальных объектов.

Проверены повторяемость независимо от бюджета работы, варианты/seed,
отмена/validation, legacy, границы/переход, stale preview, Undo/Redo,
Save/Reopen/Discard, физическая высота/navigation и preview=Apply.
Native Forward+: существующее выделение, окно/отмена, Apply с тем же candidate,
EditorUndoRedoManager, Save/Reopen/Discard и F6 по созданному рельефу прошли.
Окно ограничено размером редактора; прокрутка параметров не вытесняет кнопки.
Исправлен первый native layout с wrap-текстом: Window не растёт по временной
минимальной высоте, после layout обновляется размещение дочерних controls.
Native regression при 125%: первый/повторный popup, ошибка, размеры 1600×900
и 1280×750 (минимум нативного редактора при этом масштабе), default bounds
при metadata 72×48 / terrain 48×48 прошли. Соседние окна карты/участка
проверены без применения; общей смены их масштаба нет.
Автоматический расчёт 48×48 м — ~0,18–0,20 с; 96×96 м с изрезанным рельефом —
~0,84–0,86 с, шаг ~4,5 мс. Подготовка/полная validation измеряются отдельно;
эти цифры не являются временем 3D-сборки или замером слабого ПК.
Авторская оценка формы/параметров и удобства, проходимость сложных склонов,
карта 256–512 м, слабый ПК и специальные пробные поля воды остаются OPEN.
Следующий контракт — сохраняемая разметка нескольких областей; конкретный
контур, его owner и правила повторного Apply согласуются отдельно.

## Материалы и рабочий интерфейс

Роль `soil/grass/sand/stone` и ID варианта принадлежат слоту палитры compact
Resource. Пустая роль старой карты не угадывается по цвету. Разные слоты одной
роли могут показывать разные варианты; смена варианта обновляет атлас без remesh.
Общие `content/terrain_materials/*.tres` хранят верхний рисунок 16×16 и
необязательный `side_pixels` для боков в тех же трёх тонах, глянец, силу блика
и рельеф пикселей. Пустые бока сохраняют прежний рисунок/свет. Изменение файла влияет на все
использующие его карты; источник — `EmberCompactTerrainPattern`.

Окно паттерна использует существующую сетку Surface Canvas, протяжку, пипетку,
локальное Undo/Redo и PNG 16×16 для Aseprite. Переключатель «Верх / Боковые грани»
выбирает рисунок для штриха и PNG; отмена сохраняет нужную грань даже после
переключения. PNG сравнивается с округлёнными RGBA8-тонами собственного экспорта.
Закрытие отменяет черновик;
явное сохранение обновляет материал без remesh. 16×16 выбрано после сравнения
с 8×8; художественная приёмка фактуры и стыков ещё открыта.

Проба `scenes/compact_material_relief_study.tscn` назначает отдельные
`grass_relief/soil_relief/sand_relief/stone_relief`; оригинальные варианты и
авторские карты не заменены. Геометрия, вода и collision совпадают с исходной
водной пробой; различаются только ID материалов в её отдельном Resource.
Рельеф работает на верхних и боковых гранях; у грунта/песка — короткие слои,
у травы/камня — отдельные группы пикселей. Существующий мокрый песок сохранён.
Пользователь уточнил направление: нужна реакция на свет, а не ещё один рисунок.
`scenes/compact_material_light_study.tscn` сравнивает те же цвета/паттерны:
прежний свет, естественный мультяшный и игрушечный пластик. «Вид мира → Материалы»
меняет scene-owned `EmberMapLoader.compact_material_light_mode` (0/1/2) и
`compact_material_gray_preview`; Sun и Environment остаются владельцами света.
В F6 есть отдельное сравнение без записи; постоянный выбор делают в редакторе
через Ctrl+S. В естественном варианте глянец управляет шероховатостью,
сила блика — отражательной способностью. Пластик — общая фиксированная отделка
для сравнения; его индивидуальные настройки ещё не вводились.
Новые варианты используют плавный прямой свет, GGX/Smith/Schlick и отражение
окружения; постоянной подсветки боков нет. Пластик получает гладкую отделку и
дополнительный блик покрытия. Мокрый песок сохраняет потемнение/шероховатость.
SSAO отдельно переключается в authored Environment; MapLoader больше не
перезаписывает его флаг. Тяжёлые GI/SSIL/объёмный туман не включались.
Настройки меняют uniforms без remesh/collision и записываются в `.tscn`, не terrain.
Старые сцены сохраняют режим 0; выбор общего стиля и перенос требуют приёмки.
Forward+ сравнения — `art/references/compact-material-light-{previous,natural,plastic}.png`
и `compact-material-light-swatches-*.png`. QA проверил Undo/Redo, Save/Reopen/Discard,
свет/камеру, одноцветную пробу и настоящий F6 из нового процесса редактора.
При обновлении открытых скриптов использовать штатный Reload Open Files:
сохранение сцены может записать старый открытый буфер скрипта. Hot reload
новых look-полей согласуется у MapLoader, сохраняя живые Sun/черновик земли.
Художественная оценка, швы, живое редактирование фактуры и стоимость на слабом ПК OPEN.
Отложено: скругление геометрии для игрушек, объёмный свет, дерево/металл/ткань,
погода и перенос на карты; архивные schema/контроллеры не устанавливались.

3D-инструменты слева, параметры в `Ember · Мир` справа рядом со штатным Inspector,
сохранение сверху. Общая графитовая тема с оранжевым активным состоянием;
контекстный каталог параметров не создаёт второй owner кистей.
Пользователь принял общие кисти, параметры и плавное наведение. Узкое окно
1280×720/125%, новые материалы и полный цикл Save/Undo ещё требуют проверки.
Производные миниатюры кэшируются в `user://`; повторный запуск Godot ещё открыт.
Следующий UI-срез нижней полки — после приёмки текущего потока.

## Производительность и границы доказательств

- Overlay наведения не создаёт mesh линий. Tile сохраняют точную физическую
  поверхность, объединяют равные площадки и переиспользуются при расширении.
- Срез игровой земли без потери формы реализован (2026-10-05): тот же mesher объединяет
  соседние вертикальные полосы только при одинаковых plane/normal, low/high и
  полном цвете со semantic palette slot. Разрывы, слои и исключения сохраняются;
  вид и collision используют одни итоговые треугольники. Водная геометрия прежняя.
  По уточнению автора эта обработка нужна только игре. `build_tile` по умолчанию
  оставляет прежние непосредственные side quads; projection передаёт opt-in
  coalescing только при `not Engine.is_editor_hint()`. В редакторе нет накопления/
  сортировки spans на мазках, новая runtime policy проходит через section window,
  grouped и uniform пути. Схема/источник карты общие, editor geometry не запекается.
  На native fixture 192×120 м / 40 участков без отображения воды ground vertices
  1 367 940→861 534 (−37,0%); видимые примитивы 456 764→287 962 при прежних 1444
  draw calls. Water vertices в обеих сборках 5 362 980. Создание/подключение
  collision ~276→177 мс; общая подготовка ~14,3 с практически не изменилась,
  так как вода всё равно строилась. Paired ground-only GPU ~0,92…1,16 мс против
  ~1,27 мс, общий кадр ~4,7…5,0 мс без устойчивого выигрыша. Это RTX 5070,
  не FPS полной игры/слабого ПК. Overview PNG различались в 311 из 1 440 000
  пикселей; это дополнительная проверка растеризации, не ручная приёмка.
  Native editor/F6 прошли preview/Apply, стык, кисть/Undo/Redo, Save/Reopen/Discard
  и ходьбу через стык. После разделения дополнительно проверено: настоящий editor
  использовал прежние 774 vertices вместо runtime 18 на контрольном tile; F6
  использовал 18 и прежнюю физическую поверхность. Editor faces точно совпали
  с сохранённым QA mesher до оптимизации. Targeted mesh/projection/addressed-map/water-seam gates
  прошли; проверка semantic alpha старого mesh test приведена к текущему shader.
  Ручная проверка боковых граней/материалов, длинной кисти и ходьбы автора OPEN.
  По сообщению автора о регрессии лишняя обработка отключена для editor. Это
  разделило пути геометрии, но не устранило зависания sectioned-кисти; отдельная
  причина и проверка приведены ниже. Фоновый sleep не заменяет живой мазок.
  QA: `qa_selection/ground_geometry_paired.json`, `ground_geometry_merged.json`,
  `ground_geometry_reference.json`, `qa_ground_native_sections.log` и
  `qa_sections/play_result.json`, `qa_ground_runtime_policy_final.log` в текущей
  отдельной Ember River Preview QA.
- Sectioned-кисть: trace автора `terrain_1791196118_96762906.json` (96×120 м,
  20 участков) показал шаги 2,19/7,01 с и кадр 7,19 с при GPU ~4 мс. Mesh delta
  в последнем кадре ~27 мс, validation/dirty status не объясняют паузу. Контрольный
  шаг на отдельном fixture воспроизвёл 6,30 с: сбор колонок и projection apply
  многократно адресовали Resource/участки, проверяли соседей каждой колонки и
  повторно записывали уже опубликованные данные. Owners прежние: CompactTerrainBrush,
  BrushMath, TerrainSections и TerrainPilotProjection. Каналы теперь читаются
  пачками; section group усредняется по одному массиву; соседи инвалидируются
  только на границах tile; projection после сравнения старого документа принимает
