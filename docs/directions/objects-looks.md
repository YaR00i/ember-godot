# Объекты и облики
Обновлено: 2026-10-27. Активность: в очереди, этап6/7 общего редактора (Product Plan).

Визуальные ориентиры27.10: Genshin — детальная/low poly форма и материал, ALLfiring —
воксельные объекты/мир. Blender — методы подготовки/конвертации. Общие роли/границы —
[Product Plan](../EMBER_PRODUCT_PLAN.md#общая-фактура-материалов-для-трёх-миров).
Пиксельная подача персонажей пока исследуется отдельно в characters; новый конвертер не принят.

## Цель
Любой объект Source получает любой облик (воксели / low poly / подробный) через один вход
«Source → форма и материал». Физика, пол и навигация остаются на одной поверхности.

## Владельцы
- Камень (твёрдая оболочка): `scripts/ember_voxel_solid_surface.gd` (оболочка, живые грани, воксельный вид,
  `AUTHORED_BLOCK_M`), `scripts/ember_voxel_prop.gd` (переключатель видов, масштаб мира, пол),
  `scripts/ember_voxel_prefab.gd`, `scripts/ember_voxel_model_resource.gd`, `scripts/vox_mesher.gd`.
- Source и производные: `content/voxel_models/*.tres`, `prefabs/voxels/`.
- Деревья: `scripts/prototypes/ember_tree_*`, `addons/ember_import/ember_voxel_*tree*`.

## Принято автором
- Уточнение27.10: сохраняем действующую voxel-основу природной лепки; внешний подробный mesh →
  low poly/voxel входит отдельным этапом перед итоговой приёмкой редактора. Это игровые облики,
  а не дистанционный LOD. Первый сценарий — одна статичная природная модель; оригинал и материалы
  сохраняются, производные готовятся/кешируются заранее. Смена мира/сфера не пересобирают их заново.
  Планирование не вводит новый Source/schema: авторство правок/повторного импорта и адаптация
  в существующий редактор требуют исследования и конкретного контракта перед реализацией.
- Направление 23.10: два способа создания объектов — нынешний воксельный исходник и импорт
  подробной полигональной модели. Из выбранного исходника отдельно получать три облика;
  обязательной цепочки detailed → low poly → voxel нет. Оригинал сохраняется, объект остаётся
  единым и редактируемым. Это принятое направление; новый тип Source/schema, конвертер и правила
  правок производных ещё требуют отдельного среза. Нынешние Resources не мигрировали.
- Исторически приняты отдельные элементы кромки/рисунка — Terrain Authoring → описание формы и цвета камня.
  Уточнение автора 22.10: камень в целом, подробный облик и живые грани **не приняты**;
  выбранные значения параметров не являются художественной приёмкой результата.

  выключена прежним флагом, её настройки сохранены; подробный камень возвращён. Ручная оценка движения OPEN.

## На исследование · Blender и получение обликов
Решение автора 23.10: Blender и его открытые исходники — постоянный источник методов для Ember.
Изучать подходы, существующие библиотеки и варианты внешней подготовки, прежде чем писать аналог
самостоятельно. Собственный интерфейс и редактирование результата должны оставаться в Ember;
обязательный ручной переход в Blender для каждого действия пока не выбран. Приоритет сейчас —
[непрерывная кисть земли](editor.md#согласованный-срез--обновление-земли-без-рывков-2310).

- [Subdivision Surface](https://docs.blender.org/manual/en/5.4/modeling/modifiers/generate/subdivision_surface.html):
  Catmull–Clark, Simple, уровни детализации, сохранение нужных острых рёбер; более плотная сетка
  не восстанавливает утраченные авторские детали автоматически. Проверить применимость к
  подробному производному виду и дальнейшей лепке без потери исходника.
- [Decimate: Collapse / Un-Subdivide / Planar](https://docs.blender.org/manual/en/4.4/modeling/modifiers/generate/decimate.html):
  Collapse уменьшает число элементов с учётом формы; Un-Subdivide пытается убрать предыдущее
  подразделение подходящей регулярной сетки и не является точной обратной операцией для любой модели;
  Planar упрощает близкие плоскости с ограничителями UV/материалов/рёбер. Сравнить на одном объекте
  сохранность силуэта, отверстий и границ материалов. Low poly как художественный облик не равен простому LOD.
- [Remesh](https://docs.blender.org/manual/en/dev/modeling/meshes/retopology.html): преобразование mesh
  через объёмную сетку, выбор размера ячейки, сохранность тонких частей/объёма/материалов. Blender
  Voxel Remesh не равен готовому Ember voxel Source; проверить вывод в наши редактируемые данные.
- Сравнить три пути: подготовка через Blender, использование подходящего компонента, реализация
  нужного ограниченного метода внутри Ember. Оценить время импорта/обновления, кеш, лицензии при
  прямом переносе кода, размер зависимости и возможность правки через нынешний редактор.
- Отдельно определить авторство правок: что меняет исходник, что является поправкой одного облика,
  как повторный импорт сохраняет работу автора. Не запускать автоматическое разрушительное
  преобразование туда-обратно. Физика/пол/navigation должны иметь одну согласованную поверхность.

Связь с локальной AI-3D мастерской (проверены файлы25.10, новый запуск не выполнялся):
`D:/AI-3D/` содержит ComfyUI, ComfyUI-Pixal3D, Blender-5.2.2 и Hunyuan checkpoint.
Готовая форма — `D:/AI-3D/config/pixal3d-user/default/workflows/AI Workshop/04_Image_to_3D_Pixal.app.json`;
в ней есть Pixal3DImageTo3D/ExportGLB и AIWorkshopGLBResult для выдачи файла.
Вход/выход мастерской не равен готовому Ember-импорту. Сервер, генерация и качество нового
предмета25.10 не проверялись. Локальные инструкции — `D:/AI-3D/README_RU.txt` и Obsidian
`Проекты/Картинка в 3D — Pixal3D.md`; голый OPTIMIZE_3D.cmd удаляет UV/текстуры Pixal3D
(предупреждение подтверждено README), его нельзя считать общим текстуросохраняющим импортом.
Для мебели рекомендован небольшой предмет с проверяемыми масштабом/опорой/материалами;
импорт сохраняет исходный GLB, ручные правки и независимые производные. Автоматическое
превращение всех внешних моделей только в voxel Source не принято. Каталог/опоры/комнатные
наборы — World Authoring → «Дальнейшее направление25.10», Visual Library Design.

Первый будущий сквозной пример: одна статичная подробная модель → импорт → low poly/voxel →
редактирование параметров → save/reopen → три вида на основной карте. Универсальный конвертер,
новые кисти и анимированные модели этим исследованием ещё не реализованы.
Blender Sculpt/потоки/частичные GPU-обновления — [исследование редактора](editor.md#blender-sculpt--исследование-применимости);
стилизованный свет персонажей — [characters](characters.md#на-исследование--стилизованный-свет-персонажей).

### Модульные обрывы и склейка
Три редактируемых уступа26.10 подключены к main и прежней библиотеке: plateau/straight/corner,
трава/земля/камень. Технические Source/editor/опора/облики проверены; внешний вид/ввод OPEN.
Действующий срез — World Authoring → «Уступы v0». Ручное «Тянуть»26.10 сохраняет внешний
силуэт/слои/облики/опору одного плато; мышь OPEN. Owners — «Ручной силуэт через Canvas».
Боковая выемка/покраска26.10 сохраняются в3 видах с физической поверхностью;
owners/evidence/ограничения — World Authoring → «Единая объёмная лепка». Ручной вид OPEN;
склейка ниже этим не подтверждается.

Склейка объёмов26.10:
Автор хочет пересекать несколько камней/земляных заготовок и получать один редактируемый
объём, с травяным верхом и земляными/каменными слоями боковин. Canonical маршрут и порядок —
World Authoring → «Приоритет25.10 · карта3×3»; material rules принадлежат materials.
Действующие owners `ember_voxel_merge.gd` / merge_session / merge_dialog, прежняя команда «Склейка».
Merge.plan объединяет occupied voxel cells, считает overlap, сохраняет каналы/палитру/part IDs;
по текущему коду:2–32 input parts, согласованный масштаб, относительные повороты90°, grid align,
до32 выходных частей/524288 ячеек и совместимые material/physics. Это не произвольный mesh boolean.
Для двух solid Sources исправлен перенос guides/owners/roles/material IDs и volume topology;
выемка/покраска/3 облика, отсутствие внутренних faces, native история/сохранение проверены.
Main-пример — EarthCliffUnion; исходные assets сохранены. Generated material override больше
не блокирует операцию; настоящая ручная замена защищена. Owners/границы/evidence —
World Authoring → «Склейка объёмов26.10». Произвольные позы/мягкий union/Б на вогнутых
гранях/сфера и художественная приёмка не закрыты; mixed solid/обычный voxel явно отклоняется.
Рекомендована явная обратимая команда после сборки; автосклейка при пересечении пока идея.
Внешний detailed→low poly/voxel путь остаётся принятым направлением выше, первым предметом
с сохранённым оригиналом; до нескольких семейств и arbitrary union проверить этот один сценарий.
