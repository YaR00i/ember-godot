# Ember — направления проекта

Обновлено: 2026-10-25. Один файл на направление; статус в нём **заменяется**, не дописывается.
Единая карта проекта — `scenes/landscape_compact.tscn` (AGENTS.md → «Единая карта и направления»).

## Как пользоваться

1. Перед задачей: `../EMBER_NOW.md` (какое направление активно) и файл своего направления.
2. После среза: заменить в файле направления «Принято / Без приёмки / Открыто / Где остановились».
3. Подробности, проверки и история остаются в тематических документах; файл направления
   только ссылается на них. Одна истина в одном месте.
4. Obsidian (по желанию): открыть папку `docs/` как хранилище. Источник правды — репозиторий;
   `.obsidian/` в `.gitignore`.

Общие изменения: [Workflow](../EMBER_WORKFLOW.md) → «Общие изменения и потребители»;
техническая граница — [Handoff](../EMBER_TECHNICAL_HANDOFF.md) → «Слои и зависимости».
В «Зависимостях» назвать, что направление отдаёт и кому; в статусе — проверенных потребителей,
незакрытый общий сценарий и первое действие. PASS отдельной пробы не означает готовности всей системы.

## Зависимости (слои — Technical Handoff → «Слои и зависимости»)

Генераторы и Редактор создают Source → Объекты и облики превращают Source в форму →
Материалы одевают форму → Мир и карта размещает объекты и задаёт свет/воду/землю.
Бой и Игровые системы опираются на карту и персонажей, но не на способ получения облика.
Нижнее направление не знает верхних; планировщик (Мир и карта) знает модель и вид объекта,
но не способ его генерации.

## Шаблон файла направления (до ~60 строк)

```
# <Направление>
Обновлено: <дата>. Активность: <активно / в очереди / на паузе>.
## Цель                 (1–2 строки)
## Владельцы            (файлы, модули, ресурсы)
## Принято автором      (что и когда)
## Сделано без приёмки  (что, где проверено)
## Открыто              (вопросы, gates, долги)
## Где остановились     (первое действие для возврата)
## Зависимости          (берёт у … / отдаёт …)
## Ссылки               (документы, тесты)
```
