# Ember — переработка интерфейса мастерской

Дата: 2026-09-10. Нативная переработка выполнена по согласованному Task Contract.
Пользователь принял общую композицию, скорректированное размещение подсказок,
постоянную палитру и нижнюю полку объектов с фильтрами; полный ручной сценарий
в рабочем Godot остаётся открытым.

## Зачем

Возможности накопились в длинных панелях: пользователь не смог найти штампы.
Нужна цельная организация инструментов, а не ещё одна кнопка. Реализация одиночных
штампов существует и прошла targeted tests, но её UI пользователем не принят.
Новые функции мастерской временно приостановлены ради этого прохода.

## Реализованный результат

- Вверху виден путь `Объект → Модель → Часть → Пресет` и отдельное состояние
  `Сохранено / Не сохранено`; общие действия не смешаны с настройками кисти.
  Имя выбранного экземпляра сцены редактируется прямо в поле `Объект`, отдельно
  от имени и стабильного ID voxel-модели; операция входит в Undo/Redo сцены.
- Слева постоянно доступны основные инструменты, включая самостоятельные
  `Выделение` и `Штамп`. Активные режимы отражаются в кнопках и заголовке.
- Справа находятся только рабочие вкладки `Части / Библиотека`.
  Параметры переноса или штампа временно закрепляются над вкладками и не исчезают
  при выборе карточки. Длинные объяснения перенесены в нижнюю строку.
- Палитра закреплена отдельным компактным блоком снизу слева под инструментами:
  образцы и команды `добавить / изменить / заменить / рамп / пипетка` доступны
  при любой правой вкладке. Сетка цветов прокручивается локально и использует
  прежний PalettePanel и Undo owner, без второго состояния.
  Для swatch задан нейтральный icon tint во всех button states, поэтому выбранный
  тёмный цвет не подменяется editor-темой; освещение 3D-модели по-прежнему может
  делать видимую грань светлее самого palette data.
- Вкладка `Части` больше не является одним длинным полотном: внутри неё независимы
  `Выделение / Группы / Вид`. Способ и изменение выделения выбираются короткими
  сегментами, связанные действия собраны попарно, а группы, срез и рабочая область
  не конкурируют за высоту с текущим сценарием. Длинные имена групп и частей
  сокращаются внутри доступной ширины и больше не выталкивают controls за край.
- Библиотека использует сетку карточек. Миниатюры строятся в памяти из canonical
  `EmberVoxelModelResource`; новый кеш, schema или производные файлы не появились.
  Форма сохранения скрыта за `+ Новый штамп`, а выбранный пресет и действия
  `Разместить / Редактировать` закреплены под локально прокручиваемой сеткой.
- Библиотека объектов сцены теперь не смешана с библиотекой штампов. В 3D она
  открывается постоянной нижней полкой `Объекты`, не модальным окном: слева поиск,
  фильтры owner и карточки, справа выбранное превью, ID/размер/теги и закреплённая
  кнопка `Поставить в сцену`. Миграция и открытие Resource находятся в `Ещё…`.
  В шапке всегда указано фактическое место добавления; пока сохраняется прежнее
  +X рядом с выделенным объектом либо fallback к player_start/началу Map.
- Параметры активной операции больше не требуют раскрывать пять списков:
  режим, ось, поворот, зеркало и опора представлены короткими взаимоисключающими
  кнопками. Они управляют теми же значениями plan и не меняют расчёты штампа.
- Локальный `ember_voxel_workshop_theme.gd` централизует skin мастерской и
  накладывается поверх активной темы Godot: шрифты, editor icons и DPI остаются
  нативными, а кнопки/поля/вкладки/карточки получают графитовый фон, cyan hover,
  amber active/primary и приглушённый disabled. Остальной Godot не меняется.
- Обе боковые панели сворачиваются. Проверены 1280×720 и 1600×900, пустая
  библиотека, disabled actions, красная ошибка операции, dirty state и основной
  авторский масштаб 125%; правая панель расширена до 340 px для устойчивой
  компоновки рабочих вкладок.

Новый gate `test_voxel_workshop_layout.gd` проверяет компоновку, режимы,
сегментированные параметры, три подраздела `Частей`, длинные group/part names,
закреплённые действия
библиотеки, сворачивание, footer help, disabled/error/dirty и минимальное место вкладок.
Forward+ captures: `user://voxel_workshop_compact.png` (1280×720),
`user://voxel_workshop_parts.png`, `user://voxel_workshop_groups.png`,
`user://voxel_workshop_layout.png` (1600×900), `user://voxel_stamp.png` и
`user://voxel_object_library.png`.

## Предложенное направление для согласования

- Знакомая логика Blender/MagicaVoxel: это ориентиры интерфейса, не игровые
  референсы и не требование копировать их оформление. Нативные Godot Controls,
  согласованная тема, единый набор понятных иконок; короткие подписи для основных
  инструментов, tooltip с названием, действием и фактической горячей клавишей.
- Слева постоянный компактный набор инструментов. Штамп — самостоятельный
  инструмент рядом с выделением, лепкой и покраской, а не секция далеко внизу.
- Сверху параметры только активного инструмента. При размещении штампа видны
  Добавить/Заменить, поворот, отражение, опора; обычные настройки лепки скрыты.
- Справа вкладки палитры, частей и библиотеки. Пресеты узнаются по миниатюрам,
  не только по техническим именам. Палитра в реализации вынесена в постоянный
  левый блок, поэтому правая панель оставлена для Parts/Library. Точные координаты и расширенные параметры
  остаются доступными, но не конкурируют со всем сразу.
- Внизу короткая контекстная подсказка: что делает мышь, Enter, Esc, Shift/Ctrl.
  Применить/Отменить и состояние несохранённых изменений всегда различимы.
- Явно различать объект сцены, выделенные воксели, часть и пресет. Отдельные
  команды общей модели/уникальной копии не теряют предупреждений.
- Адаптивная компоновка при открытом инспекторе и Output, без ухода кнопок за
  границы. Скролл локальный для длинного содержимого, не поиск основной команды.

## Выполненный порядок работы UI-координатора

1. Read-only ориентация и инвентаризация существующих команд, состояний и owners.
2. Короткий Task Contract и один цельный макет. Предпочтителен нативный прототип
   для настоящей темы и размеров Godot; HTML не обязателен. Пользователь
   согласует композицию и логику до массового переноса панелей.
3. На макете пройти три сценария: лепка; выделение и перенос; сохранение,
   выбор и размещение штампа. Проверить также disabled/error/dirty состояния.
4. Перестроить существующий UI небольшими законченными шагами, без второго
   workspace и дублирования команд. Отдельно проверить вход из 3D/инспектора.
5. Targeted regressions, нативная Forward+ проверка, ручная приёмка пользователя;
   обновить NOW/handoff/gates и подготовить возврат в основной чат.

## Существующие владельцы и границы

`addons/ember_import/ember_voxel_sculpt_workspace.gd` владеет Canvas;
`ember_voxel_selection_panel.gd`, `ember_voxel_selection_interaction.gd` —
выделением и размещением; `ember_voxel_stamp_panel.gd` — библиотечным UI.
Чистые `ember_voxel_stamp.gd`, `ember_voxel_fragment.gd`, `ember_voxel_merge.gd`
остаются владельцами расчётов. Object/assembly/extraction/merge sessions сохраняют
сценовые транзакции. Источник геометрии — `EmberVoxelModelResource`, не UI.

Не менять формат моделей, renderer, физику, правила склейки и происхождение
вокселей, сохранение или базовую математику ради оформления. Не добавлять пока
непрерывный штамп, 2D-паттерны, воду, генераторы или игровой контент. Изменение
существенного поведения требует отдельного согласования, не прячется в UI-refactor.

## Приёмка

- Все прежние команды найдены и доступны; активный инструмент и следующий шаг
  понятны без объяснения расположения кнопки в чате.
- Предпросмотр совпадает с применением; один Undo/Redo, Escape/Cancel, save/reopen,
  discard, независимые/общие экземпляры, world placement и collision сохранены.
- Существующие stamp/selection interaction/fragment/merge/extraction/object canvas
  tests и затронутые regressions проходят. Тесты пишут только fixtures/user://.
- Проверить реальный Godot Forward+: обычный и узкий Canvas с инспектором/Output,
  масштаб интерфейса пользователя, фокус ввода чисел и горячих клавиш.
- В Object Canvas переименовать экземпляр в шапке, проверить пустое/повторяющееся
  имя, Undo/Redo и сохранение нового имени после Ctrl+S и повторного открытия сцены.
- Ручной сценарий: открыть деталь Причала → лепить → выделить/перенести → отменить →
  сохранить выделение как штамп → найти его по миниатюре → Добавить/Заменить →
  отменить/применить → сохранить сцену → перезапуск → F6. Это не заменяется тестами.

## Большой план и возвращение

Полный принятый план уже сохранён в [продуктовом плане](EMBER_PRODUCT_PLAN.md),
раздел «Воксельная мастерская окружения». Он остаётся каноническим: объектный
цикл → формы/сборка → склейка/разделение → оба вида кистей → дно/вода/Причал.
Не создавать конкурирующий список статусов. После UI вернуться к незавершённым
кистям (2D-маска с глубиной, непрерывность/шаг) и затем воде по новым контрактам.
Игровая глава сохранена в GDD и продуктовом плане; её наполнение приостановлено.
После основного редактора отдельно провести согласованную Q&A-сессию по GDD.

Передача временная и только UI: основной чат остаётся открытым, пользователь
вернётся после UI. Новый координатор сам исследует, пишет и тестирует, без
субагентов. До согласованного макета не начинать перестройку. По завершении
передать изменённые owners, checkpoint, тесты, ручную приёмку и оставшиеся долги.

## Проверка checkpoint перед передачей

10 сентября повторно прошли 9 headless scripts: test_voxel_stamp,
test_voxel_selection_interaction, test_voxel_merge, test_voxel_extraction,
test_voxel_object_canvas, test_combat_status_resource, test_combat_grid,
test_party_save_v2, test_test_pier. Команда для каждого:
`tools/godot/Godot_v4.7.2-stable_win64_console.exe --headless --path . --script res://tools/<name>.gd`.
`git diff --check` прошёл. Это выборочная проверка checkpoint, не полный regression.
Object Canvas/Причал ранее сообщали invalid UID для mesh ящиков
`prefabs/voxels/meshes/vox_fan_crate_stack_block.res`, затем загружали его по
пути. После ручной приёмки UI stale UID в prefab заменён актуальным UID самого
mesh; повторный `test_voxel_object_canvas.gd` прошёл без предупреждения.

Накопленное состояние сохраняется как checkpoint, не как утверждение общей
готовности: реализованные инструменты и авторский Причал; незавершённая приёмка
штампов; отдельные накопленные игровые изменения party/statuses и художественные
листы Миры. Последние сохраняются, но не входят в полномочия UI-координатора.
Пользователь выбрал тот же локальный checkout; основной чат не пишет параллельно.

После фазы 3 последовательно прошли 11 scripts: `test_voxel_workshop_layout`,
`test_voxel_stamp`, `test_voxel_selection_interaction`, `test_voxel_fragment`,
`test_voxel_merge`, `test_voxel_extraction`, `test_voxel_object_canvas`,
`test_combat_status_resource`, `test_combat_grid`, `test_party_save_v2` и
`test_test_pier`. `git diff --check` прошёл. Forward+ на RTX 5070 подтвердил

остаётся один ObjectDB leak в fragment gate; fallback crate mesh устранён.
