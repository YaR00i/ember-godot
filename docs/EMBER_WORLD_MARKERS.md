# Ember — world markers

## Назначение

World marker быстро отвечает на один вопрос: «с этим объектом сейчас есть осмысленное действие?». Он не заменяет журнал, не раскрывает заблокированные этапы и не превращает зону исследования в список служебных значков.

Референсы используются как UX-наблюдения, а не как источник графики:

- [Octopath Traveler II](https://samurai-gamers.com/octopath-traveler-2/map-and-radar-icons-guide/) отличает крупную сюжетную цель от доступной side story цветом, размером и миганием.
- [Final Fantasy XIV UI Guide](https://na.finalfantasyxiv.com/uiguide/know/faq-display/interface_npc_icon.html) меняет иконку по состоянию и отдельно обозначает важный/открывающий контент.
- [Final Fantasy XIV Game Manual](https://na.finalfantasyxiv.com/game_manual/view/) разделяет надголовные NPC-маркеры, цели и ориентиры minimap вместо одного универсального символа.
- [Godot Label3D](https://docs.godotengine.org/en/stable/classes/class_label3d.html) и [StandardMaterial3D](https://docs.godotengine.org/en/stable/tutorials/3d/standard_material_3d.html) подтверждают штатные billboard/fixed-size/no-depth-test механизмы для 3D-индикаторов.

## Визуальный язык v1

- `available` — янтарный гранёный жетон с `!`: новое действие или задание.
- `active` — голубой ромб-компас: текущая цель или место продолжения.
- `done` — мятный жетон с галочкой: последняя обязательная цель либо доступная сдача.
- `locked` — не показывается в мире. Причина блокировки остаётся в журнале.

Цвет никогда не является единственным различием: состояния имеют разные силуэты и внутренние знаки. Все три SVG оригинальны для Ember и лежат в `res://assets/world_markers/`; сторонней лицензии или runtime-addon нет.

## Поведение

- Маркер якорится над центром верхней грани видимого Mesh и сохраняет прежний clearance.
- До 140 world units он имеет стабильный экранный размер. Затем плавно уменьшается; после 190 одновременно затухает и на 300 исчезает.
- SVG 64×64 использует `Sprite3D.pixel_size = 0.00175`: экранный размер близок к ранее принятому 30 px `Label3D`, без возврата гигантских glyph.
- `billboard + fixed_size` принадлежат штатному `Sprite3D`; parent `QuestMarker` является единственным anchor/LOD pivot.
- `no_depth_test` пока сохраняет читаемость top-down кадра. Отдельное roof/occlusion-решение должно менять общий marker policy, а не ставить исключения конкретным домам.
- Unknown custom `iconId` не теряется в данных, но runtime показывает status fallback, пока для ID не создан asset в общей библиотеке.
- Маркер связан с `EmberQuestResource` через `quest_id`: свой `statusFlagId` и SVG он получает автоматически. Исполняемая цепочка объекта хранится отдельно в `script_id`, поэтому одна метка может одновременно показывать состояние задания и завершать выбранную цель.
- Роль не хранится отдельным enum/key. `set_flag(statusFlagId, active)` в цепочке означает выдачу, запись objective flag — конкретную цель, `set_flag(statusFlagId, done)` — сдачу. Это та же action schema и тот же save v1.
- Выдача видна только до принятия; цель — только когда задание начато, все её зависимости выполнены и она ещё не закрыта; сдача — только после всех обязательных целей. Выполненное событие исчезает и перестаёт принимать F.
- Если доступная цель является последней невыполненной обязательной целью, она заранее использует мятную галочку: взаимодействие с этим объектом завершит набор обязательных целей.
- Стандартные `quest_available`, `quest_active`, `quest_done` являются dynamic state aliases. Зафиксировать можно только отдельный custom icon ID.
